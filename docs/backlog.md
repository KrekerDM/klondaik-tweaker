# Что ещё можно сделать

Разбор чужого твикера по скриншотам интерфейса, сверенный с нашим каталогом. Чужой код не смотрели и не копировали: здесь список возможностей
Windows, которые там есть, а у нас нет или сделаны грубее.

Пометки: **нет** — у нас отсутствует, **частично** — есть похожее, но уже,
**есть** — закрыто.

## Сделано 20.09.2026

Каталог вырос со 148 до 171 твика. Закрыто:

- вся **телеметрия разработчика** — .NET, PowerShell, общие CLI-инструменты,
  Visual Studio, телеметрия лицензирования
- **HPET**, **UCPD**, **брандмауэр**, **автошифрование BitLocker**,
  **уведомления Защитника**, **автоустановка Teams**, **автообновление карт**,
  **фоновая работа Edge**
- интерфейс: **сжатие обоев**, **старый просмотрщик фото**, **динамическое
  освещение**, **экран блокировки**, **Spotlight**, **старый Alt-Tab**, **все
  значки в трее**, **Центр мобильности**, **Новости и интересы**,
  **всплывающие уведомления**
- **бейдж «не поддерживается»** с объяснением причины: раньше неприменимые
  твики просто исчезали из списка без следа
- **пункты контекстного меню** «Запуск от имени TrustedInstaller» и «Стать
  владельцем» — переключаются на вкладке «Инструменты»
- **вкладка «Компоненты Windows»** — 27 компонентов через DISM, с описанием
  каждого и пометкой, что из этого небезопасно держать включённым
- **вкладка «Задачи планировщика»** — 12 групп и 54 задачи с объяснением, что
  делает каждая группа

Не взято из-за неуверенности в ключах: телеметрия веб-камеры, приоритетный
фильтр WFP, HDCP, AMSI, Code Integrity, разделение mitigations на отдельные
уязвимости. Эти нужно сначала проверить по документации, а не угадывать.

## 1. Целые модули, которых у нас нет

Это не отдельные твики, а вкладки со своей логикой. Самое крупное из
пропущенного.

### 1.1. Прерывания и привязка к ядрам

Отдельная вкладка: список устройств (GPU, хост-контроллер мыши, сетевая
карта), под каждым сетка потоков процессора с разделением на **P-Core и
E-Core**, и прерывания устройства привязываются к выбранным потокам.

Плюс глобальный переключатель «блокировка маршрутизации прерываний».

Как делается: `HKLM\SYSTEM\CurrentControlSet\Enum\<инстанс устройства>\Device
Parameters\Interrupt Management\Affinity Policy` — значения `DevicePolicy`,
`AssignmentSetOverride` (битовая маска ядер), `DevicePriority`. Классы P/E-ядер
берутся из `GetSystemCpuSetInformation`.

Зачем: это реально снижает задержки ввода и микрофризы в играх, потому что
прерывания GPU и мыши перестают попадать на те же ядра, что и фоновая работа.
Одна из самых ценных вещей в списке.

**Сложность: высокая.** Нужен разбор дерева устройств и topology процессора.

### 1.2. Расширенные свойства сетевого адаптера

Вкладка со всеми advanced properties выбранной сетевой карты и тремя
пресетами: по умолчанию / оптимальное / **low latency**.

Параметры с экрана: энергосберегающий Ethernet (EEE), управление потоком (flow
control), **модерация прерывания** (interrupt moderation), контрольная сумма
разгрузки IPv4/TCP, большой кадр (jumbo frame), разгрузка при большой отправке
v2 (LSO), выгрузка ARP и NS, приоритет и VLAN, буферы приёма и передачи,
скорость и дуплекс.

Как делается: `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e972-...}\<NNNN>`
— имена значений у каждого вендора свои (`*FlowControl`, `*InterruptModeration`,
`*ReceiveBuffers`, `*LsoV2IPv4` и так далее), список доступных значений лежит в
подключе `Ndi\Params`. Правильный путь — читать `Ndi\Params` и строить интерфейс
из него, а не хардкодить.

У них видно состояние «по умолчанию» и «отредактировано» для каждой строки —
хорошая идея, у нас такого нет нигде.

**Сложность: высокая.** Но это честный выигрыш по сетевой задержке.

### 1.3. Диспетчер устройств

Список устройств с переключателями и отдельной секцией «ненужные устройства»:
перечислитель композитной шины, перечислитель виртуальных дисков, UMBus
перечислитель корневой шины, перечислитель виртуальных сетевых адаптеров NDIS.
Плюс групповые: Bluetooth, принтеры, WAN Miniports.

Как делается: SetupAPI (`SetupDiGetClassDevs`, `SetupDiSetClassInstallParams` с
`DICS_DISABLE`) или `pnputil` / `Disable-PnpDevice`.

**Опасно:** отключить не то устройство — потерять диск или сеть. Нужен жёсткий
белый список и запрет трогать загрузочный контроллер.

### 1.4. Компоненты Windows

Вкладка с optional features: .NET Framework 3.5, компоненты прежних версий,
мультимедиа, службы печати и документов, печать в PDF, XPS, SMB Direct, Work
Folders Client, сервер контейнера, службы IIS, службы для NFS, Remote Desktop
Services, Windows Identity Foundation.

Как делается: `DISM /Online /Get-Features`, `Enable-WindowsOptionalFeature` /
`Disable-WindowsOptionalFeature`. Заблокированные компоненты показываются
отдельным состоянием.

**СДЕЛАНО.** Вкладка «Компоненты»: 27 компонентов с человеческими описаниями,
сгруппированы по смыслу, помечены «можно отключить», «осторожно» и
«небезопасно». Всё, что включено, но нам не известно, показывается отдельной
группой. Каждое переключение пишется в журнал и откатывается.

### 1.5. Панель NVIDIA

Профили драйвера NVIDIA: глобальный профиль, поиск конкретной игры, импорт и
экспорт настроек, пресет «оптимальное».

Как делается: NVAPI (`NvAPI_DRS_*`) или правка профилей через `nvidiaProfile
Inspector`-подобный подход над `nvdrsdb0.bin`. Официального публичного API для
этого нет, поэтому реализация рискованная и ломается с драйверами.

**Сложность: высокая, стабильность низкая.** Скорее всего не стоит того.

## 4. Идеи по интерфейсу

Вещи, которые у них сделаны лучше, и это видно.

1. **Бейдж «NOT SUPPORTED»** прямо на карточке твика, который к этой системе
   не применим. У нас есть состояние `Unavailable`, но оно выглядит как обычный
   неактивный переключатель — непонятно, сломано или так задумано.

2. **«При отключении не будет работать: …»** — конкретный список функций,
   которые сломаются, а не общая фраза. Примеры с экранов: «Быстрый ALT+TAB»,
   «LastActivityView», «Принтер», «VPN», «XBOX», «Центр безопасности (UI)»,
   «Запуск игр в лаунчере EA», «Использование сети в Диспетчере задач». У нас
   поле `warn` есть, но формулировки размытее. **Это самое дешёвое улучшение из
   всего списка: переписать warn у всех 148 твиков в формат «сломается ровно
   это».**

3. **Три пресета на каждой вкладке**: по умолчанию / оптимальное / максимум.
   У нас пресеты только на вкладке твиков и они глобальные.

4. **Выпадающие списки вместо тумблеров** там, где значений больше двух:
   Win32PrioritySeparation, задержка контекстного меню, внешний вид, обновления
   (в том числе «Пауза» как отдельное состояние).

5. **Значок нагрева** у твиков, влияющих на температуру, и **череп** у
   необратимых. У нас есть уровни риска, но нет отметки «назад не вернёшь».

6. **Сворачиваемая «Подсказка»** в шапке каждой секции.

7. **Кнопка «Обновить»** на каждой вкладке — пересканировать состояние.

## 5. Что из этого брать первым

По соотношению «польза к работе»:

1. **Переписать `warn` у оставшихся твиков** в формат «сломается ровно это».
   Бейдж для неприменимых уже сделан, новые твики уже написаны в этом формате,
   осталось пройтись по старым 148.
2. **Телеметрия разработчика** — шесть твиков через переменные окружения.
3. **HPET и динамический тик через bcdedit** — мы это пропустили, а твик
   заметный.
4. **UCPD** — без него смена браузера по умолчанию откатывается обратно.
7. **Мелкие твики интерфейса** — сжатие обоев, старый просмотрщик фото,
   динамическое освещение, экран блокировки, Alt-Tab, трей.
8. **Разделить mitigations** на Spectre v2 / Meltdown / Downfall.
9. **Вкладка «Задачи»** по образцу нашей вкладки служб.
10. **Электропитание: импорт и экспорт .pow, разблокировка скрытых параметров.**
11. **Прерывания и привязка к ядрам** — самое ценное для игр и самое сложное.
12. **Расширенные свойства сетевой карты** — строить интерфейс из `Ndi\Params`.

Отдельно: панель NVIDIA через NVAPI брать не стоит, ломается с каждым
драйвером.
